# ADR-0033: Frontend ↔ backend contract through generated OpenAPI

- **Status:** Accepted (tool confirmed in M2: orval)
- **Date:** 2026-11-21

## Context
WORKFLOW.md said "Zod schema shared with backend", but the monorepo has no shared package. Without a contract, the frontend would retype every DTO by hand and drift silently.

## Decision
1. The REST contract is the **OpenAPI document generated by `nestjs-zod` + Swagger** (Decision #7, #13).
2. `pnpm --filter api openapi:export` writes `apps/api/openapi.json`, which is **committed**. CI fails if it is out of date (`git diff --exit-code`). Every API change shows up as a diff in the PR.
3. The frontend generates a typed client, TanStack Query hooks and Zod schemas from that file (proposal: `orval`; confirm in M2). Output in `apps/web/src/api/generated/` (gitignored, generated before dev and build).
   **Confirmed in M2 (`feature/web-foundation`):** `orval` (`apps/web/orval.config.ts`) with two outputs, split by tag: a `react-query` client whose functions all call the mutator `src/api/http.ts` `request`, and a `zod` client (`*.zod.ts`) for forms. `override.operationName` turns Nest's `AuthController_me` into `authMe` (hooks `useAuthMe`, `getAuthMeQueryKey`). The document is OpenAPI 3.1, the syntax Zod 4 uses for nullable fields.

   **Envelope:** the document describes what the controller returns (`UserResponseDto`), while the wire carries the `ResponseInterceptor` envelope (`{ success, data }`, or `{ success, data: items, meta }` for a list). `request` applies the exact inverse (`unwrapEnvelope`: `data`, or `{ items, meta }`), so generated types match what callers receive. Swagger UI shows the unwrapped shape. Error bodies are not in the document; their one shape (ADR-0001) is hand-written in `http.ts`.
4. WebSocket payloads reuse the REST response DTOs (ADR-0025), so their types come from the same file. Event names and the envelope type are a short hand-written list in `apps/web/src/realtime/events.ts`, mirroring `apps/api/src/modules/realtime/realtime.events.ts`. Checked in review.

## Alternatives considered
| Option | Rejected because |
|---|---|
| `packages/shared` with Zod schemas imported by both apps | The API compiles and tests as CommonJS (Decision #14), Vite is ESM. A shared TypeScript package needs its own build plus path mapping in Jest, Nest and Vite. Codegen keeps one source (the backend) with no build coupling |
| Hand-written frontend types | Drift is found only at runtime |

## Consequences
Breaking API changes follow expand → migrate → contract (ADR-0036): the deployed frontend must keep working against the new API until it is redeployed.

The generated document can be wrong while the API is right: Zod → nestjs-zod → @nestjs/swagger → orval is a chain of translations. A contract test compares the type of every DTO property in the document with Zod's own JSON schema (`test/openapi.e2e-spec.ts`). Known gaps it caught in M2: a nullable property became an array (fixed by `nestjs-zod` 5.6); a string with several `.regex()` lost its `type` and then produced invalid orval code (fixed by `restorePatternTypes` in `openapi-document.ts`).
